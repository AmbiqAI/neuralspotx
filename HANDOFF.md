# HANDOFF: docs migration, P1a reference generation (#258)

## Goal

Stand up `astro-site/` on Astro, Starlight and `@ambiqai/helia-ui` with the five-section
shell and a build-and-validate workflow that runs on pull requests, on pushes to main and
on demand, with no deploy step. No content migration. Part of
the migration plan in `tasks/256-docs-migration/plan.md` (parent AmbiqAI/neuralspotx#256).

## Current state

Done and verified locally on macOS (Node 24.12.0, npm 11.6.2):

- `npm ci` from a clean tree, `npm run check` (0 errors, 0 warnings, 0 hints),
  `npm run build` (3 s wall, 6 HTML pages, 1.6 MiB dist), `npm run validate` (links,
  assets, anchors, Pagefind index, footer provenance) all pass.
- Home renders with no desktop sidebar (`data-helia-sidebar-layout="mobile-only"`); the
  four section pages get a scoped sidebar.
- `pre-commit run --all-files --hook-stage manual` passes.

Not verified: a real Linux CI run (the workflow has never executed), and any visual review.
Visual review is scheduled for P2 and P4 in the plan, not here.

## Decisions and why

- **Directory `astro-site/`**, matching heliaRT, so the two sites stay comparable (plan §1,
  §6).
- **helia-ui pinned to `github:AmbiqAI/helia-ui#v0.1.0-alpha.14`**, resolved commit
  `95eb9f1d2dc461533ed2c9477d6d52d0ab4969e5`, lockfile committed (plan §5).
- **Teal accent through `src/styles/site-theme.css`, not the plugin's `accent` option.**
  helia-ui's `PRODUCT_ACCENTS` has no neuralSPOT-X entry, so the dial carries
  `--helia-product-accent: #0d8f88`, the same value the MkDocs site uses in
  `docs/stylesheets/extra.css`. Both sites therefore read as one product while both are
  live. Upstream: AmbiqAI/helia-ui#115.
- **Sections Home / Getting started / Guides / Modules / Reference**, Modules as its own
  top-level section (plan §2, owner decision §7.1).
- **Footer provenance from `pyproject.toml` plus the git commit**, generated by
  `scripts/build-info.mjs` into `src/data/build-info.json` (gitignored, regenerated by
  `pre*` scripts). Reading the version from `pyproject.toml` keeps release-please as the
  single writer (plan §3).
- **`validate` is a Node script, not heliaRT's Python one.** RT's `check-site-links.py` is
  generic but its `check-output.mjs` is product-specific; rewriting the portable link and
  anchor pass in Node keeps the workflow on one runtime.
- **Discoverability: ogImage, jsonLd and markdown on, llms off.** The first three are free
  on a site that already has an absolute `site`; the llms bundle is #261's scope.
- **Home transcript: which lines are verbatim.** The command lines and
  `nsx hello from generated app` are verbatim, the latter from
  `docs/getting-started/first-app.md`. The success line is edited: the format string in
  `operations/_app_lifecycle.py` is `Created app '<name>' at: <dir>`, and `api/_app.py`
  passes an `expanduser().resolve()` path, so the CLI always prints an absolute directory.
  The page shows `/home/you/hello_ap510` as a stand-in for the reader's own path.
- **`deploy-pages.yml` untouched.** MkDocs keeps publishing until the cutover (#261).

## P1a (#258) reference generation: done, verified locally

The whole Reference section is generated by `astro-site/scripts/build-reference.mjs`,
which `prepare:docs` runs before every dev, check and build. 80 Python symbols on 6
pages, 35 CLI pages covering 18 distinct commands, 14 subcommands and 3 aliases, 4
configuration schemas; 0 unresolved cross-references; generation takes about 0.9 s.
Nothing generated is committed. Completeness is enforced by
`tests/test_reference_generation.py` (37 tests)
and `astro-site/scripts/check-reference-output.mjs` (wired into `npm run validate`).
Full detail, decisions and measurements in `tasks/256-docs-migration/p1a-notes.md`;
new upstream gap drafts in `tasks/256-docs-migration/helia-ui-gaps-258.md`.

Budgets, decided rather than open: the per-page uncompressed HTML budget for Python API
pages is 640 KB rather than the 250 KB the C++ reference uses, because a Starlight shell
is about 100 KB before content and 250 KB would cap a page near ten symbols. Gzip stays
at 40 KB. The largest page sits at 77% of the HTML budget and 78% of the gzip one, and
the check warns at 80% so it gets split before it fails.

## Gotchas

- `astro.config.mjs` imports `src/data/build-info.json`, which is generated. Every script
  that loads the config needs the `pre*` hook, `check` included. `npm run check` fails
  with "Unable to load your Astro config" without it.
- The lockfile records helia-ui as `git+ssh://git@github.com/AmbiqAI/helia-ui.git#<sha>`,
  which is how npm writes any `github:` spec. `AmbiqAI/helia-ui` is public, so a runner
  with no SSH key still installs it: npm falls back to HTTPS for a hosted git spec.
  heliaRT ships the identical lock entry and its CI is green. No token is needed.
- The lockfile was generated on macOS but carries every platform's optional binaries
  (65 linux-scoped entries, 0 required platform-scoped packages), so `npm ci` on Linux
  resolves without a rewrite.
- Three build warnings are Starlight and Astro internals with no site-side fix: the
  MDX `use astro:head-inject` directive note, the empty `i18n` collection, and the `/404`
  route priority note. Declaring an empty `i18n` collection trades one warning for two.
- helia-ui parts are imported through the export map (`@ambiqai/helia-ui/astro/<Part>`).
  Do not reach into `node_modules` by relative path and do not patch it.

## helia-ui gaps, filed upstream

Each was hit building this scaffold. None blocks the site; the workarounds are in the
files named below and should be revisited when an issue closes.

- AmbiqAI/helia-ui#115: no product accent for neuralSPOT-X and no escape hatch on the
  `accent` option. Worked around in `astro-site/src/styles/site-theme.css`.
- AmbiqAI/helia-ui#116: no footer slot for build provenance, so the version and commit
  ride in a link label in `astro-site/astro.config.mjs`.
- AmbiqAI/helia-ui#117: the plugin header renders the site name as text, so Starlight's
  `logo` config is inert. Only the favicon is observable today.
- AmbiqAI/helia-ui#118: `AsciiTerminal` types out `command` lines only, so the Home
  demo's output and success lines appear at once.
- AmbiqAI/helia-ui#119: `site-theme.css` reads as copy-the-whole-file; this site copies
  two dials, which works but is undocumented.
- AmbiqAI/helia-ui#120 (question): pyref emits pages for private modules.
- AmbiqAI/helia-ui#121: pyref leaves cross-references unresolved for types re-exported
  through the package root. The raw griffe dump showed 105 unresolved references; see
  `tasks/256-docs-migration/helia-ui-gaps-258.md`.

#120 and #121 are the two that matter for #258; both are recorded in plan §8 with the
measurements behind them.
