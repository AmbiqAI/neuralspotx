# HANDOFF — docs migration, P0 scaffold (#257)

## Goal

Stand up `astro-site/` on Astro, Starlight and `@ambiqai/helia-ui` with the five-section
shell and a PR-only build-and-validate workflow. No deploy, no content migration. Part of
the migration plan in `tasks/256-docs-migration/plan.md` (parent AmbiqAI/neuralspotx#256).

## Current state

Done and verified locally on macOS (Node 24.12.0, npm 11.6.2):

- `npm ci` from a clean tree, `npm run check` (0 errors, 0 warnings, 0 hints),
  `npm run build` (3 s wall, 6 HTML pages, 1.6 MiB dist), `npm run validate` (links,
  assets, anchors, Pagefind index, footer provenance) all pass.
- Home renders with no desktop sidebar (`data-helia-sidebar-layout="mobile-only"`); the
  four section pages get a scoped sidebar.
- `pre-commit run --all-files --hook-stage manual` passes.

Not verified: a real Linux CI run (the workflow has never executed), and any visual review.
Visual review is scheduled for P2 and P4 in the plan, not here.

## Decisions and why

- **Directory `astro-site/`**, matching heliaRT, so the two sites stay comparable (plan §1,
  §6).
- **helia-ui pinned to `github:AmbiqAI/helia-ui#v0.1.0-alpha.14`**, resolved commit
  `95eb9f1d2dc461533ed2c9477d6d52d0ab4969e5`, lockfile committed (plan §5).
- **Teal accent through `src/styles/site-theme.css`, not the plugin's `accent` option.**
  helia-ui's `PRODUCT_ACCENTS` has no neuralSPOT-X entry, so the dial carries
  `--helia-product-accent: #0d8f88`, the same value the MkDocs site uses in
  `docs/stylesheets/extra.css`. Both sites therefore read as one product while both are
  live. Upstream candidate, see Gaps.
- **Sections Home / Getting started / Guides / Modules / Reference**, Modules as its own
  top-level section (plan §2, owner decision §7.1).
- **Footer provenance from `pyproject.toml` plus the git commit**, generated by
  `scripts/build-info.mjs` into `src/data/build-info.json` (gitignored, regenerated by
  `pre*` scripts). Reading the version from `pyproject.toml` keeps release-please as the
  single writer (plan §3).
- **`validate` is a Node script, not heliaRT's Python one.** RT's `check-site-links.py` is
  generic but its `check-output.mjs` is product-specific; rewriting the portable link and
  anchor pass in Node keeps the workflow on one runtime.
- **Discoverability: ogImage, jsonLd and markdown on, llms off.** The first three are free
  on a site that already has an absolute `site`; the llms bundle is #261's scope.
- **Home transcript uses only verified command output.** `Created app 'hello_ap510' at:`
  came from running `nsx create-app`; `nsx hello from generated app` is from
  `docs/getting-started/first-app.md`.
- **`deploy-pages.yml` untouched.** MkDocs keeps publishing until the cutover (#261).

## Gotchas

- `astro.config.mjs` imports `src/data/build-info.json`, which is generated. Every script
  that loads the config needs the `pre*` hook, `check` included — `npm run check` fails
  with "Unable to load your Astro config" without it.
- The lockfile records helia-ui as `git+ssh://git@github.com/AmbiqAI/helia-ui.git#<sha>`.
  That is fine on a runner with no SSH key because the repo is public and npm falls back
  to HTTPS for a hosted git spec; heliaRT ships the identical entry and its CI is green.
  If helia-ui ever goes private, CI needs a token.
- The lockfile was generated on macOS but carries every platform's optional binaries
  (65 linux-scoped entries, 0 required platform-scoped packages), so `npm ci` on Linux
  resolves without a rewrite.
- Three build warnings are Starlight and Astro internals with no site-side fix: the
  MDX `use astro:head-inject` directive note, the empty `i18n` collection, and the `/404`
  route priority note. Declaring an empty `i18n` collection trades one warning for two.
- helia-ui parts are imported through the export map (`@ambiqai/helia-ui/astro/<Part>`).
  Do not reach into `node_modules` by relative path and do not patch it.
