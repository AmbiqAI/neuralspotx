<Band density="compact">
  <SectionHeader
    eyebrow="Capabilities"
    title="What NSX does."
    description="Six things, each one a command you can run and a file you can read afterwards. Nothing NSX generates is hidden from you."
  />
  <CardGrid columns={3} equalize>
    <LinkCard
      title="Scaffold an app"
      titleAs="h3"
      eyebrow="Create"
      href="/neuralspotx/getting-started/first-app/"
      meta="nsx create-app --board apollo510_evb"
      lift
    >
      `nsx create-app` writes a complete app directory for a real board: an `nsx.yml`, a
      `CMakeLists.txt` and sources. Pass `--template npu-tflm` to start from a
      model-inference app instead of a blank one.
    </LinkCard>
    <LinkCard
      title="Pull in modules"
      titleAs="h3"
      eyebrow="Registry"
      href="/neuralspotx/guides/modules/using-modules/"
      meta="nsx module add"
      lift
    >
      The packaged registry pins 50 firmware modules. `nsx module search` finds one,
      `nsx module add` writes it into your `nsx.yml`, and the catalog records what each
      module provides and which boards its manifest declares.
    </LinkCard>
    <LinkCard
      title="Lock and sync"
      titleAs="h3"
      eyebrow="Reproducibility"
      href="/neuralspotx/guides/modules/lock-and-sync/"
      meta="nsx lock"
      lift
    >
      `nsx lock` records a content hash for every resolved module in `nsx.lock`, so the
      next `nsx sync` fetches the same trees on another machine. `nsx sbom` exports the
      resolved set.
    </LinkCard>
    <LinkCard
      title="Build with plain CMake"
      titleAs="h3"
      eyebrow="Toolchains"
      href="/neuralspotx/guides/system/toolchains/"
      meta="nsx build"
      lift
    >
      A generated app is ordinary CMake and Ninja that you can read, edit and build
      yourself. Board descriptors declare three toolchains: `arm-none-eabi-gcc`, `armclang`
      and ATfE.
    </LinkCard>
    <LinkCard
      title="Flash it and watch"
      titleAs="h3"
      eyebrow="On the board"
      href="/neuralspotx/guides/apps/build-flash-view/"
      meta="nsx flash && nsx view"
      lift
    >
      `nsx probes` lists the SEGGER J-Link probes it can see, `nsx flash` programs the
      board over SWD, and `nsx view` streams SWO output back from the firmware while it
      runs.
    </LinkCard>
    <LinkCard
      title="Check before you debug"
      titleAs="h3"
      eyebrow="Environment"
      href="/neuralspotx/getting-started/doctor/"
      meta="nsx doctor"
      lift
    >
      `nsx doctor` reports what it found for CMake, Ninja, the Arm toolchain and J-Link,
      and what each missing piece would cost you. `nsx doctor --json` hands the same report
      to a script.
    </LinkCard>
  </CardGrid>

  In order: [Create your first app](/neuralspotx/getting-started/first-app/),

  [Lock and sync](/neuralspotx/guides/modules/lock-and-sync/),

  [Check your environment](/neuralspotx/getting-started/doctor/).

  <HomeStats />

  The packaged registry pins 50 modules. NSX ships 17 board descriptors across 11 SoC
  families, declaring 3 toolchains between them, and this repository carries 10 example
  apps. The [module catalog](/neuralspotx/modules/catalog/) lists every module and the
  [board matrix](/neuralspotx/modules/boards/) lists every board, with the SoC, tier, SDK
  provider, CPU and toolchains each one declares.

  `nsx commands --json` prints the whole command graph, including which command each one
  leads to next, and `nsx doctor --json` prints the environment report in the same form.
  Append `.md` to any page URL on this site to get that page as Markdown, or start from
  [llms.txt](/neuralspotx/llms.txt). The module snapshot behind the catalog is published
  as [modules/catalog.json](/neuralspotx/modules/catalog.json), and every command, option,
  Python symbol and manifest field is in the [Reference](/neuralspotx/reference/). There is
  also [agent guidance](/neuralspotx/guides/contribute/agent-guidance/) for working in the
  repository itself.
</Band>

    NSX is Beta and is supported for evaluation: use it for bring-up, profiling,
    validation and demos rather than for production you cannot revise. Public symbols
    carry the
    **Provisional** stability tier: the name is public and supported, and it may still
    change before 1.0. Pin an exact version of `neuralspotx` anywhere it is a dependency of
    something you ship, and record that version alongside the artifacts it produced. See
    [Releases and versioning](/neuralspotx/reference/releases/) for how versions are
